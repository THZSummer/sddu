# ADR-001: review/validate 自主策略指引范式选型 — 混合方案

## 状态
PROPOSED

## 背景
spec FR-005~010 要求 review 和 validate Agent 解除对 plan §5.8/§5.9 的结构性依赖，改为自主定义审查清单（C1~CN）和验证场景（V1~VN）。这是 v3.0.0 "职责回归改造"的核心目标。

然而，18 个已完成 Feature 的实证表明：plan §5.8/§5.9 从未产出过任何具体 C1~CN 或 V1~VN（所有 18 个 plan.md 的 §8/§9 均为相同的 3 行通用表格）。问题的根源不是 review/validate "不够好"，而是"plan 代笔策略"这一架构前提本身是错误的——技术设计者不可能在生产前预知生产后应该怎么检查。

如果单纯删除 plan 的策略章节而不为 review/validate 补充自主方法指引，存在"空洞化"风险：review/validate 首次面对"自己定义策略"的自由时，可能因缺乏指引而产出比改造前更差的结果（spec EC-005，discovery R-001——"把 50 分底线的纸撕掉后直接交白卷"）。

因此需要在 Agent 模板层面设计一种自主策略指引范式，使 review/validate 能够：
- 知道自己应该从哪些输入中提取审查/验证对象
- 知道自己应该从哪些维度进行审查/验证
- 知道什么是"足够好"的最低质量门槛
- 有结构化输出位置呈现自主定义的 C1~CN/V1~VN

## 决策
我们决定采用 **混合方案（维度清单 + 结构化模板 + 质量门槛）** 作为 review/validate 自主策略指引范式。

### 三层指引架构：

**第一层（维度种子 — Agent 模板 §5 已有方法论）**：
- review Agent §5.1~5.4 已定义四维审查能力（代码质量 / 规范符合性 / 架构一致性 / 测试质量）
- validate Agent §5.1~5.5 已定义五维验证能力（测试覆盖 / 接口与数据 / 构建与脚本 / 性能与边界 / 漂移检测）
- Agent 模板的 §1/§5.0 改写后将**显式引用**这些已有维度作为策略设计的种子

**第二层（输出格式 — 输出模板新增 section）**：
- review 输出模板新增 `## 2. 自主审查清单 (C1~CN)` section：审查对象 + 审查基准 + 评估结果
- validate 输出模板新增 `## 2. 自主验证场景 (V1~VN)` section：验证对象 + 验证步骤 + 预期结果 + 实测结果

**第三层（质量门槛 — Agent 模板内嵌最低标准）**：
- 待用户决策（plan §8 开放问题，选项 1 vs 选项 2）
- 当前推荐选项 1：每个 FR ≥ 1 个 Cx/Vx + 每个审查/验证维度至少 1 条

### 替代方案对比：

| 维度 | 方案 A：纯结构化模板 | 方案 B：纯启发式指引 | 方案 C：混合（本决策） |
|------|:--|:--|:--|
| 空洞化风险 | 低（有模板填充） | **高**（"自主展开"语义模糊） | **低**（有维度种子） |
| 灵活性 | 低（过度约束） | 高 | 中高（可增减维度） |
| 可维护性 | 中（需维护模板结构） | 高（文本即可） | 中高（与现有方法论衔接） |
| 与现有模板对齐 | 需额外设计 | 需防止过于泛化 | **自然衔接**（§5 已有方法论） |

## 后果

### 正面影响
1. **质量底线保障**：三层指引（维度种子 + 输出格式 + 质量门槛）确保 review/validate 首次自主设计策略时不会"交白卷"
2. **与现有架构自然衔接**：review/validate 的 §5.1~5.5 本身就是天然而非泛化的审查/验证方法论（已实战验证过，如 FR-SKILL-001 的 C1~C18），不需要额外发明新概念
3. **可迭代**：如果首次自主设计质量不理想，Agent 模板中的指引文本可以渐进增强，不需要架构翻新
4. **dogfooding 闭环**：本 Feature（FR-AGENT-SCOPE-001）自身就是首个使用新策略的 Feature——后续 review/validate 阶段的产出将直接验证这套范式的有效性

### 负面风险
1. **指引粒度平衡**：维度清单太细可能限制 Agent 判断力，太粗又可能失去指引价值——需要在实施阶段精确控制指引文本的详略程度
2. **质量门槛的选择**：过于宽松（无门槛）可能导致劣化，过于严格（每个 FR × 每个维度都要求）可能催生"凑数"行为——需由用户最终决策

### 实施要点
- review Agent §1: 在角色定位中加入"自主从 spec+plan+产物中提取审查对象，运用 §5.1~5.4 审查方法论定义 C1~CN"
- validate Agent §1: 在角色定位中加入"自主从 spec+NFR+产物中提取验证对象，运用 §5.1~5.5 验证方法论定义 V1~VN"
- 输出模板新增 section 的结构化字段需与 Agent 模板中的指引保持语义一致
- 质量门槛的具体量化值（如"每个 FR≥1 个 Cx"）待用户从 plan §8 的两个候选中选择后，写入 Agent 模板
