## 2. 上下文
> 回顾问题背景和目标用户

`@sddu-roadmap` 是 SDDU 唯一「有真实落盘产物却无专属输出模板」的 Agent：它产出 `.sddu/ROADMAP.md`（当前项目实测 1382 行 / 19.0.0 版），但输出格式由指令 §5 内联的一段约 47 行骨架「约束」，而该骨架已**事实失效**——真实产物含「项目状态速览 / 关键警示 / 功能完成时间线 / 已完成版本回顾 / 跨版本 RICE 总排名 / 附录 A 文件覆盖率 / 附录 B 全量审计」等 9 个骨架外章节。用户以当前 ROADMAP 为反面教材，原话：**「AI 简直是随心所欲，完全看不懂」**。

两重根因：

1. **结构无权威来源（Q-001）**：格式定义嵌在指令正文里，与实际产物脱节，规范失去约束力 → 章节命名/顺序/粒度随 LLM 自由发挥，下游无法建立稳定预期。
2. **偏离框架统一模板逻辑（Q-002 / Q-003）**：其余 8 个有产物的 Agent §6 均为「用户自定义模板（优先）`.sddu/templates/agents/output/sddu-X.md.hbs` > 插件内置模板（兜底）`.opencode/plugins/sddu/templates/output/sddu-X.md.hbs`」两级查找；`@sddu-roadmap` 是唯一例外（§6 声明「内置固定格式，不通过外部模板文件定义」）。同时框架规范自相矛盾：FR-TPL-001 FR-021 / EC-004 规定辅助 Agent（roadmap/tree/docs）不走模板覆盖，FR-DOCS-OPT-001 却为 docs 交付了 20 个模板。附带缺陷：§1 职责边界笔误（同段同时声明「输出: 特性清单 + 版本路线图」与「不负责: …不输出版本路线图」）。

**用户已决策（RT-001~005，本 spec 不再追问）**：① 统一逻辑、支持覆盖（修订 EC-004）；② 动机 = 消除结构漂移；③ 单文件 + 增量更新（排除多文件），roadmap 定位 = 精简的顶层规划；④ 不迁移现存 `.sddu/ROADMAP.md`，本 Feature 只升级框架本身；⑤ roadmap 与 docs 互相独立，不做关联。

**目标用户**：SDDU 框架维护者（本项目 dogfooding，ROADMAP 主要读者）、ROADMAP 下游读者/Agent（需按稳定结构定位章节）、有 ROADMAP 自定义口径需求的用户（希望在 `.sddu/templates/` 下覆盖）、SDDU 贡献者、框架使用者（下游项目，后续按新模板自行迁移）。

**本次范围严格限定为设计态源码**（`src/`，必要时 `scripts/`），依据 README §209-211「项目约束（Agent 必读）」——`.opencode/`（安装产物）与 `.sddu/`（流程产物）不得列为实现目标。

### 3.1 目标 (Goals)
> 明确本次要达成的业务目标

| # | 目标描述 |
|---|---------|
| G-001 | **消除 roadmap 输出结构漂移** — 以专属外部模板替代已失效的 §5 内联骨架，使 ROADMAP 的章节集合与顺序唯一、可预期、可读、可被下游稳定解析引用（对应 Q-001 / 动机 RT-002） |

### 5.1 规范修订声明（SUP-001 / SUP-002）

> **SUP-001 — 修订并取代 FR-TPL-001 关于辅助 Agent 输出模板的例外条款**
>
> **修订对象**: `specs-tree-template-quality-unification`（FR-TPL-001）的 **EC-004**（原文：「辅助 Agent 的『输出模板』节内容与主流程 Agent 不同 → 声明其输出为内置固定格式，不走用户自定义模板覆盖路径」），以及 **FR-021** 中的同义表述（原文：「辅助 Agent（roadmap/tree/docs）按 EC-004 标注输出为内置固定格式，不走用户自定义模板覆盖路径」）——**修订范围限于其中涉及 `@sddu-roadmap` 的部分**。
>
> **修订后规则（自本 Feature 交付起生效）**:
> 1. `@sddu-roadmap` **不再**声明「输出为内置固定格式 / 不通过外部模板文件定义 / 不走用户自定义模板覆盖路径」。其输出结构由**外部 Handlebars 模板** `sddu-roadmap.md.hbs` 定义，该模板是 `.sddu/ROADMAP.md` 的**唯一权威格式来源**。
> 2. 模板加载遵循与 8 个主流程 Agent **完全一致的两级查找优先级**：
>    - **用户自定义模板（优先）**: `.sddu/templates/agents/output/sddu-roadmap.md.hbs`
>    - **插件内置模板（兜底）**: `.opencode/plugins/sddu/templates/output/sddu-roadmap.md.hbs`（设计态源文件 `src/templates/outputs/sddu-roadmap.md.hbs`）
> 3. `<<变量名>>` 占位符替换、模板使用规则、模板缺失显式报错、渲染失败回退等行为，一律与统一约定相同（见 FR-007 / NFR-004 / NFR-005 / EC-001 / EC-002）。
> 4. 本条款同时**取代** FR-TPL-001 中「辅助 Agent 一律不适用模板覆盖」的表述；`@sddu-tree`（已降级为 Skill）、`@sddu-docs`（已交付模板库）的既有处置不受影响，后续 Agent 的统一判定标准由 **FR-010** 表述。
>
> **生效方式与工程边界（重要）**: 本声明是本 Feature `spec.md`（`.sddu/specs-tree-root/specs-tree-roadmap-output-template/spec.md`）的规范条款，自本 Feature 交付即生效；**不经由修改 `specs-tree-template-quality-unification/spec.md` 实现**——该文件属 `.sddu/` 流程产物，不在本 Feature 的工程修改范围内（NG-004 / NG-005）。review / validate 阶段须以本条款为准判定规范一致性，不得据已被取代的旧条款判为「规范不一致」。

> **SUP-002 — 修订 FR-003「固定章节骨架」为 8 个 H2（新增「特性索引」）**
>
> **修订对象**: 本 spec（FR-ROADMAP-TPL-001）**FR-003** 及其「固定章节骨架表」（原文：骨架 = **7 个 H2 章节**：项目愿景与定位 / 版本总览 / 优先级（RICE Top N） / 版本规划详述 / 依赖与风险 / 下一步行动 / 修订记录）。
>
> **修订后规则（自本条款生效起）**: 骨架修订为 **8 个 H2 章节**——在「版本总览」之后、新增 **「特性索引」** 章节（对应 zone `feature-index`，`mode="rewrite"`，实时投影 `.sddu/specs-tree-root/` 下各 Feature 的 `state.json`）；其余 7 个章节的名称与相对顺序不变，「修订记录」恒为**最后一个 H2**。H2 合计 8 个，仍满足 FR-006 的「H2 章节数 ≤ 8」上限（现为**恰好 8**）。
>
> **修订理由**: 本 spec §1 职责边界与 §2 均声明 `@sddu-roadmap` 的输出为「**特性清单** + 版本路线图」，但修订前 7 个 H2 中**没有任何位置**承载"特性清单"——`version-overview` / `priority` / `version-plan` 仅零星点名 Feature，`.sddu/specs-tree-root/` 下 24 个 Feature 中仅 5 个被提及且 **0 个**带目录锚点，导致 roadmap 与 specs-tree 之间出现**断层**（用户反馈原话：「缺少特性清单，与 specs-tree 承接不起来……那么多特性哪里来的」）。新增「特性索引」章节（Feature ID / 名称 / specs-tree 目录名 / 状态 / 版本归属，`mode="rewrite"` 实时投影）为「特性清单」补齐承载位，并**逐行**给出目录锚点，使 roadmap 内每一处 Feature 引用均可走到 specs-tree 对应目录。
>
> **边界不变**: 「特性索引」仅承载**索引级**字段；FR-006 的排除内容（单 Feature 实现细节、任务级待办清单、现状审计 / 文件覆盖率 / 全量审计 / 代码级盘点，以及「不含逐 Feature **明细**表」）**继续禁止**——**索引 ≠ 明细**，二者在 plan / agent 指令中以显式规则区分。本条款不改变 FR-006 的其余约束（H2 ≤ 8、单文件篇幅指导上限 ≤ 400 行、内容准入 = 仅跨版本 / 项目级信息）。
>
> **生效方式与工程边界**: 与 SUP-001 同——本条款是本 Feature `spec.md` 的规范条款，自生效即**取代 FR-003 原表述**；review / validate 阶段以本条款为准判定结构一致性，不得据已被取代的 FR-003 原文（7 个 H2）判为「规范不一致」。配套决策见 `ADR-004-feature-index-section.md`。

> **命名空间消歧**: 本文档 §7 的 `EC-00x` 均为**本 Feature 自有**边界情况；摘要/plan/review 中单独出现的「EC-004」若不限定文档，均指 **FR-TPL-001 的 EC-004**（SUP-001 修订对象）。

## 6. 非功能需求 (NFR)
> 性能、安全、可用性等跨切面需求

| ID | 类别 | 需求描述 | 验收标准 |
|----|------|---------|---------|
| NFR-001 | 一致性 | 模板的章节命名、层级、表格写法、元数据头格式、缩进（空格）须对齐现有模板统一约定（FR-TPL-001 FR-021） | 与 `src/templates/outputs/sddu-plan.md.hbs` 等既有模板逐项比对，风格一致；无 Tab 缩进 |
| NFR-002 | 构建一致性 / 确定性 | `npm run build` 后 dist 模板与 src 源文件逐字节一致；构建幂等可重复 | 连续两次 `npm run build` 后 dist 产物 `diff` 无差异 |
| NFR-003 | 工程边界合规 | 修改目标仅限 `src/`（必要时 `scripts/`）；不修改 / 新增 / 删除 `.opencode/` 与 `.sddu/` 下的任何文件 | 变更集 ⊆ {`src/templates/outputs/sddu-roadmap.md.hbs`, `src/templates/agents/sddu-roadmap.md.hbs`, 可选 `scripts/*`}，可由 `git status` 核对 |
| NFR-004 | 可覆盖性 | 用户自定义模板优先级生效，路径与命名与既有约定一致（SUP-001 第 2 条） | 放置 `.sddu/templates/agents/output/sddu-roadmap.md.hbs` 后，生成动作使用该模板而非内置模板 |
| NFR-005 | 健壮性 / 失败可见 | 模板缺失或渲染失败时**显式报错或回退并提示**，不得静默编造输出格式 | EC-001 / EC-002 场景可复现且提示文案明确 |
| NFR-006 | 可解析性 | 章节标题稳定（编号 + 固定名称），下游可按标题字符串稳定定位，不因单次生成内容不同而漂移 | 同一模板的章节标题集合与顺序在多次生成间完全一致 |
| NFR-007 | 可维护性 | 模板为纯静态骨架 + 占位符，无渲染期逻辑代码；篇幅可控 | 模板行数 ≤ 200 行；不含 `<script>` / JS 逻辑片段 |
| NFR-008 | 向后兼容 | 不改产物路径、不改 RICE 方法论、不影响其他 10 个 Agent 的模板与行为 | 其他模板文件哈希不变；其他 Agent 指令内容不变 |

## 7. 边界情况 (EC)
> 异常场景和边界条件的处理方式

| ID | 场景 | 处理方式 |
|----|------|---------|
| EC-001 | 用户在 `.sddu/templates/` 与插件内置目录**均无** `sddu-roadmap.md.hbs` | **显式报错并终止**：「❌ 未找到可用的输出模板 sddu-roadmap.md.hbs，请确保至少存在用户自定义模板或内置模板」；不自行编造格式（对齐 docs EC-010 先例） |
| EC-002 | 用户自定义模板存在但渲染失败（Handlebars 语法错误 / 变量缺失） | **回退内置模板**并提示：「⚠️ 自定义模板 sddu-roadmap.md.hbs 渲染失败：{错误信息}，已回退到内置模板」 |
| EC-003 | 首次生成：`.sddu/ROADMAP.md` 不存在 | 按模板**全量生成**，`生成方式` 取「完整生成」 |
| EC-004 | 既有 `.sddu/ROADMAP.md` 为旧 / 非模板结构（本 Feature **不迁移**，RT-004） | **非破坏性处理**：提示「当前文档非模板结构」，由用户决定（按新模板重构 / 保留现状 / 仅增量补充）；**不静默重写、不自动迁移**（见 FR-012） |
| EC-005 | 用户自定义模板与内置模板同时存在 | 用户自定义模板**优先**；用户模板与内置模板章节骨架差异较大时，提示可能的结构漂移风险 |
| EC-006 | 模板某章节不适用于当前场景（如项目尚无风险项） | 允许标注「不适用」或省略该章节**内容**，但不得改变章节集合与顺序、不得删除章节标题骨架（保持 NFR-006 可解析性） |
| EC-007 | 增量更新时既有内容超出 FR-006 的精简上限（如正文超 400 行 / 章节超 8 个） | **提示收敛或外移**（实现细节 → spec/plan；任务清单 → tasks；现状审计 → docs），不静默截断、不静默扩章 |
| EC-008 | 规划内容粒度本身需要「分片 / 多文件」才能承载 | 判定为**超出 roadmap 定位**（RT-003 明确排除多文件）：不生成多文件，提示该场景应由独立项目 / Feature 承载，roadmap 仅保留顶层摘要 |
| EC-009 | 项目目录为空 / 无任何 Feature 可扫描 | 沿用现状：基于用户口头描述从零规划，并在文档中标注「初步规划」 |
| EC-010 | 规划产出的章节标题被下游工具 / Agent 按字符串解析 | 由于 NFR-006 保证标题稳定，解析方无需版本适配；模板变更若引发标题变更，须显式记录于模板修订记录 |
