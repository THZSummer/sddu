# ADR-015: 场景特定能力不入框架——外部 API 文档缓存门禁退役（能力丢失排查 L2）

## 状态
PROPOSED（2026-11-24 用户拍板：L2 裁决 A——退役）

## 背景
能力丢失排查（capability-loss-audit.md L2）发现一条无决策记录即消失的能力链：

- **spec 阶段**：标记外部 API 依赖时提示运行 `/sddu:api-docs` 命令
- **plan 阶段**：规划前扫描 spec 中 API 提及 → 查 `.sddu/api-docs/` 缓存 → **缺失则拒绝规划**（硬门禁）
- 载体：`.sddu/api-docs/` 目录 + `/sddu:api-docs` 命令 + sddu-spec/sddu-plan 模板中的门禁段

该链路在 v6 全部决策（plan §5.1/§5.2、ADR-001~014、workspace 骨架清单）中零出现——属黑盒丢失候选。

## 决策
**退役，不蒸馏、不迁移**。理由：

1. **SDDU 是框架级、逻辑级的存在**——适用于各个场景的 spec-driven 框架，流程本质（7 阶段问题解决）与场景无关；
2. **不做具体场景的事情**——「外部 API 文档缓存」是具体开发场景的增强：涉及 API 的项目自然有价值，但不涉及 API 的项目（文档项目、运营流程、非代码团队）该门禁完全无意义；
3. **场景增强属于用户侧**——需要 API 文档前置的项目，可经 `.sddu-config/` 的 `sddu-plan-before.md` 钩子自行写入「检查 API 缓存再规划」的个性化要求（ADR-011 已固化：钩子即最简扩展点）；框架不为特定场景内建门禁。

## 对既有设计的修订
- 无 §5.1/§5.2 结构变更（api-docs 链本就不在新设计内）。
- **模块迁移约束**：`sddu-spec` / `sddu-plan` 模板自 src/templates/agents/ 迁入 modules/ 时，**删除 API 缓存门禁段**（含 `/sddu:api-docs` 提示与 `.sddu/api-docs/` 检查），此为 MOVE+MODIFY 的显式修改点，列入 build 阶段任务。

## 后果
- 正面：框架保持场景中立（与平台中立 ADR-006 同构的原则——平台指针不入内核，场景增强同样不入）；sddu-plan 模块更精炼；涉及 API 的项目仍有钩子路径满足需求。
- 负面：API 密集型项目失去开箱即用的前置缓存门禁——已判定可接受（用户钩子一条指令即可恢复同等约束）。
- 不可逆性：低——门禁段是纯文本指令，如未来需要可在钩子或模块中随时恢复。
- 原则沉淀：**「框架级 = 逻辑级 = 场景无关」**——后续任何「为某类项目内建便捷能力」的提案均以本 ADR 为驳回依据。
