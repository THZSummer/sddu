# ADR-001: 内核采用「单一文档 + 引用」而非构建期派生/结构化渲染

## 状态
PROPOSED

## 背景
spec FR-001/FR-002 要求方法论内核成为唯一权威来源，且口径变更「改一处、全生效」。实现路径有三：方案 A（内核文档 + 各载体引用声明）、方案 B（内核 Handlebars partial 化，构建期物理注入 11 个 Agent 模板）、方案 C（方法论建模为 TS 结构化常量，双平台渲染）。B/C 提供机制级同步，但均需改造现有构建链（build-agents.cjs 现为原样复制、build-dsh-skills.cjs 受「只拼接不改写」约束）。

## 决策
采用方案 A：
1. `sddu.md`（仓库根）为方法论唯一权威文档，内容覆盖 7 阶段流程、三原则、两字段状态模型、各阶段文档契约，零平台特定事实；
2. 各载体（Agent 模板 / SKILL.md / README / dev-guide）的方法论转写段替换为「权威来源：sddu.md」引用声明，仅保留平台/阶段特有行为指令；
3. **内核随安装分发**：sddu.md 进入两平台安装产物各一份（OpenCode 随插件包 `.opencode/plugins/sddu/sddu.md`；dsh 置于路由 skill `.dsh/skills/sddu/sddu.md`），其余载体以相对路径引用（`../sddu/sddu.md`）——安装态同样维持「单一副本 + 引用」，不随 skill 数量复制内核。

「改一处全生效」的语义 = 改内核即全生效——各载体仅持引用声明、不转写方法论，无副本可漂移；同步由「无副本」而非校验或渲染机制保证。（2026-11-24 修订：开发期校验脚本 check-essence-sync 随「无副本」消解漂移源而退役）

## 后果
- 正面：改动集中、不碰渲染管线；内核平台中立、可独立阅读与分发（为 skill 市场推广与非编程领域延展预留路径）；与「简化」版本目标自洽（不为简化先增重）。
- 负面：无（各载体仅引用不转写，改内核即全生效，已无漂移源；结构一致性由 e2e 回归保证）。
- 演进：若未来需要机制级同步，可在内核与引用之上增量升级为方案 B/C，无沉没成本。
