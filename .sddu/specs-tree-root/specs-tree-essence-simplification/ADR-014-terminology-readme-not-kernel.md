# ADR-014: 术语表不进 sddu.md——内核保持精炼，形象化描述归 README；build 命名维持（评估 B4 拒绝+非问题）

## 状态
PROPOSED（2026-11-24 用户拍板）

## 背景
多视角评估（非代码团队视角）对 v6 提出两项：
1. **术语门槛**：「本体」「内核」「specs-tree」「四维判据」「门禁」「契约」「路由表」等术语对非代码团队构成认知门槛，建议在 sddu.md 加术语表；
2. **build 语义失真**：7 阶段中 build 一词对写作等内容型项目语义漂移（实际是「写初稿」），建议改名。

## 决策
1. **术语表不进 sddu.md，要加就加到 README**：
   - sddu.md 是方法论内核，**尽量不要太繁琐冗余**——内核的读者是 Agent，术语精确性优先；内核自身必须保持自包含的精炼，不为认知门槛加辅助层；
   - **分层阅读路径已自然存在**：Agent 读完 sddu.md 还搞不懂 sddu 框架，那就继续读 README（ADR-013 已将 README 入本体 `.sddu/.sddu/README.md`，与本体内核同目录、随装即得）——README 承担**更形象贴切的描述**（含术语的人话解释），是内核的对外释义层；
   - 内核管精确、README 管形象，职责二分而非内核内嵌辅助内容。
2. **build 命名非问题，维持不变**：spec-driven 领域 build 是行业通用阶段名（Kiro 等同用），改名 implement 同样技术味且是大爆炸重命名；内容型语义映射本质是 v12 多平台/多内容形态适配议题，不属于 v6 本质简化范围。

## 对既有设计的修订
- 无结构性变更；README（ADR-013 已入本体）在「本质先行」结构中自然涵盖形象化描述职责，本 ADR 仅固化该职责归属。

## 后果
- 正面：sddu.md 保持内核精炼（不为辅助内容增重）；README 职责明确（对外形象释义层）；7 阶段命名稳定。
- 负面：非代码团队需经 README 二跳理解术语——已判定可接受（README 随装即得、路径浅）。
- 不可逆性：无——纯职责归属固化；术语表如未来需要，落点已定为 README。
