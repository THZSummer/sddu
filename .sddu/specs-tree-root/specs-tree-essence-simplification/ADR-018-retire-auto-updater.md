# ADR-018: 文件驱动自动推进退役——插件事件驱动属平台限定业务，框架不包容（能力丢失排查 L5）

## 状态
PROPOSED（2026-11-24 用户拍板：L5 裁决 C——完全退役）

## 背景
能力丢失排查（capability-loss-audit.md L5）发现的完整能力链：

- `auto-updater.ts`：由产物文件反推 phase（`inferCurrentPhaseFromFiles`）→ 自动 `updateState` 推进（triggeredBy='auto-updater'）
- 触发源：**OpenCode 插件的平台事件**——`file.edited`（文件编辑，防抖 5s）/ `session.idle`（会话空闲全量扫描）
- 保护语义：FR-003（status≠tracked 跳过）、严格前进不回退、父特性限制、仍走完整校验+依赖拦截

该链路在蒸馏清单中无位置，属黑盒丢失候选。

## 决策
**完全退役，不蒸馏、不迁移**。理由：

1. **它是 OpenCode 插件的内容**——整个触发链挂在插件的生命周期事件（file.edited / session.idle / session.created / session.end）上，离开 OpenCode 宿主事件体系即无从触发。dsh 侧本就无此能力（两平台不等价）；
2. **当前设计不包容平台限定的业务**——与 ADR-015（场景特定能力不入框架）同构的裁决原则：**平台特定的运行时机制同样不入框架**。框架级/逻辑级的存在只依赖「Agent 读 md 执行」这一平台无关契约；
3. **新范式下推进职责归协议内建**——Agent 完成阶段产物的同一动作序列内更新 state.md front-matter（完成协议，A8 底稿条目），无需外部事件驱动的事后反推。

## 对既有设计的修订
- 无 §5.1/§5.2 结构变更（auto-updater 在 src/ 整目录 DELETE 伞形范围内）。
- **蒸馏范围明确排除**：TASK-002 底稿不含「文件反推 phase」「自动推进」语义（底稿 A9 的「以 phaseHistory 为权威而非文件反推」条款保留——它本来就是修这个机制的缺陷）。
- **A8 完成协议**成为阶段推进的唯一路径（Agent 写完产物即更新 state.md，无事后触发）。

## 后果
- 正面：框架零平台限定运行时机制；OpenCode 事件耦合彻底切断；state.md 推进路径唯一（完成协议），无「事件驱动」与「协议驱动」双轨竞争。
- 负面：失去「Agent 忘更新 state 时的文件反推兜底」——已判定可接受：对账漂移由 e2e 结构回归暴露（L6 裁决方向一致），且文件反推本身有 builded/reviewed 无法区分的已知缺陷。
- 不可逆性：低——触发机制若未来需要（如 v12 平台增强），属平台适配层议题，不回内核。
- 原则沉淀：**「插件事件驱动 = 平台限定业务」**——凡依赖宿主平台生命周期事件的能力，一律属平台适配层，不入框架内核。
