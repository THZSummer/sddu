## 2. 上下文
> 回顾问题背景和目标用户

方法论本质（7 阶段问题解决流程 + 不跳步/不越界/文档即状态 + 两字段状态模型）无单一权威表达，散落于 11 个 Agent 模板、README、docs、dev-guide、dsh SKILL.md 多处转写副本，且已出现口径漂移（Q-001，P-037 为实证）；载体（模板/Skill/插件/平台适配）在无判定约束下持续膨胀——45 模板三层分发、五处同源同步、ROADMAP 1045 行、技术债台账约 45 项、26 个迁移残留文档（Q-002，P-042 登记）。用户已拍板方向：「回归本质，回归方法论的本质，其余的内容全部属于附属品、模板、skill、插件等等」，范围限定两大支柱：方法论内核蒸馏 + 载体瘦身。

目标用户：项目负责人/维护者（消除多层同步负担）、新用户/评估者（先见本质后见载体）、下游阶段 Agent（获得唯一本质参照）、贡献者（获得「本质 vs 附属品」判定依据）。

## 3. 目标与非目标
> 明确需求范围，防止范围蔓延

### 3.1 目标 (Goals)
> 明确本次要达成的业务目标

| # | 目标描述 |
|---|---------|
| G-001 | 方法论内核蒸馏：产出单一、最小、平台中立的方法论核心表达，作为唯一权威来源 |
| G-002 | 载体降位瘦身：按可判定标准对既有载体分类并执行削减/合并，载体一律降位为可替换附属品 |
| G-003 | 路线图重估：按同一标准对 v7~v12 未实施提案逐项重估（保留/搁置/合并），结论回填 ROADMAP |
| G-004 | 复杂度可度量下降：给出简化前后可量化对比（文档规模 / 模板数 / 同步点数） |

### 3.2 非目标 (Non-Goals)
> 明确本次不涉及的范围，防止需求蔓延

| # | 明确不做 |
|---|---------|
| NG-001 | 不实现 dsh 硬门禁 / 模板渲染 seam（平台执行能力，留 v12.0.0 多平台二期） |
| NG-002 | 不做 adapter 契约收敛重构（P-041 主体，v12.0.0 范围） |
| NG-003 | 不修复 4 个预存失败测试（P-005，v7.0.0 质量闭环范围） |
| NG-004 | 不删除任何已交付且仍在使用的用户能力，除非用户对该项显式确认（类 HARD-GATE 语义） |
| NG-005 | 不新增载体能力（本版本只减不增——唯一新增产物是方法论内核表达本身） |

## 5. 功能需求 (FR)

| ID | 需求描述 | 验收标准 | 优先级 |
|----|---------|---------|--------|

| FR-002 | **载体表述对齐**：Agent 模板（src/templates/agents/）、dsh SKILL.md、README、dev-guide 中的方法论表述改为引用内核或由内核派生，消除独立转写副本 | ① 抽查各载体方法论关键口径（阶段顺序/三原则/状态枚举）与内核一致；② 演练一次「内核口径变更」只需改内核一处即可使各载体同步（同步链路有定义且可执行） | P0 |
| FR-003 | **判定标准定义**：定义「本质 / 附属品」可操作判定标准（候选维度：删除后 7 阶段流程是否仍成立 / 是否平台特定 / 是否历史包袱 / 是否服务流程本身），并附边界项裁决规则 | ① 标准成文且维度可操作；② 用标准回放分类既有载体清单，无「无法归类」项（边界项均有裁决记录） | P0 |

| FR-005 | **瘦身执行（用户确认制）**：分类清单中「可删/可合并」项逐批提交用户显式确认后执行；确认记录留痕；裁撤后双平台 7 阶段流程仍可完整走通 | ① 每个裁撤项有用户确认记录（无静默裁撤）；② 裁撤后 e2e basic 通过、dsh 侧 11 skill 静态结构测试通过；③ 保留载体与分类清单一致 | P0 |
| FR-006 | **路线图重估**：按判定标准对 v7~v12 全部未实施提案（PR-001~PR-012、PR-015、PR-016、PR-007，共 14 项）逐项重估，产出保留/搁置/合并结论并回填 ROADMAP | ① 14 项提案每项有重估结论与依据；② ROADMAP §3/§5/§6 按结论更新（状态/版本归属如实反映） | P0 |
| FR-007 | **历史状态数据迁移**（清障快项）：29 个 Feature 的 state.json 中 19 个数字 phase（6/7）迁移为 v3.0.0 字符串 phase；FR-DSH-ADAPT-001 的 version 误写（v3.0.0→v5.0.0）更正 | 全部 state.json 通过状态口径校验（check-essence-sync 以 sddu.md 为权威逐文件断言；validateStateV3 随 TS 退役废弃——ADR-005） | P1 |

## 6. 非功能需求 (NFR)
> 性能、安全、可用性等跨切面需求

| ID | 类别 | 需求描述 | 验收标准 |
|----|------|---------|---------|
| NFR-001 | 平台中立性 | 内核文档零平台特定事实 | 关键词扫描（.opencode/.dsh/opencode/dsh/安装命令/平台路径）零命中 |
| NFR-002 | 不降级 | 瘦身不损害双平台既有可用能力 | e2e basic 通过；dsh 静态结构测试（skill-package.test）通过；安装链路自检通过 |
| NFR-003 | 可维护性 | 方法论口径变更收敛为「改一处、全生效」 | 同步点数较简化前下降且有前后对比记录（五处同源同步 → 内核引用） |
| NFR-004 | 可追溯性 | 每个裁撤决策可追溯（判定条款 + 用户确认记录） | 抽样任意裁撤项可还原决策链 |
| NFR-005 | 可度量简化 | 简化效果可量化 | 交付物含前后对比表：README 行数 / 模板数 / 文档数 / 同步点数 / ROADMAP 行数 |
| NFR-006 | 可扩展性（FR-008） | 新增平台零框架变动（仅限支持 `.agents/skills` 约定的平台；不内置指针等适配机制） | 假想平台 demo：仅新增一个入口 md 完成安装；`git diff` 证明模板与脚本零改动 |
| NFR-007 | 升级安全（FR-008） | 安装/升级对用户产物零副作用 | 安装前后 `workspace/` 逐字节比对一致；旧布局迁移有备份与回滚 |

## 7. 边界情况 (EC)
> 异常场景和边界条件的处理方式

| ID | 场景 | 处理方式 |
|----|------|---------|
| EC-001 | 裁撤引发回归（对应 R-001） | 每个裁撤项配回归验证场景；未通过则回滚该项并记录，不阻塞其他项 |
| EC-002 | 判定标准遇到争议边界项（对应 R-002） | 边界项标记「待用户裁决」并集中列出，逐项显式拍板，不静默归类 |
| EC-003 | 与 v12.0.0 时序耦合（对应 R-003） | 保持「本质先行」次序：v6 期间冻结 adapter 契约大重构；若重估结论要求拉前 v12 相关项，须用户显式确认后再调整路线图 |
| EC-004 | 文档生态同步不完整（对应 R-004） | 载体表述对齐（FR-002）以检查清单验收，未对齐项登记为待办而非静默放过 |
| EC-005 | 历史数据迁移失败（FR-007） | 逐文件报告失败原因，不静默跳过；失败文件不阻塞其余迁移 |
| EC-006 | 台账悬空（对应 R-005） | 裁撤后 ROADMAP 问题台账逐项核对，对象消失的问题标记「已关闭-对象裁撤」，不留悬空登记 |
| EC-007 | 存量旧布局迁移失败（FR-008） | 安装器检测旧 `.sddu/` 根下布局 → 备份 → 迁入 `workspace/`；任一步失败即整体回滚到迁移前状态并逐项报告，不产生半迁移 |
