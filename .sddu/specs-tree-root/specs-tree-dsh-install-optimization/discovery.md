## 1. 问题定义
> 概括核心问题及其业务影响，回答"为什么需要关注"

| 核心问题 | 业务影响 | 不解决的成本 |
|---------|---------|------------|
| dsh 安装流程缺一键引导层，四步分散（clone + build + install + 启动），无 opencode 式 bootstrap 入口 | 全新环境安装 SDDU 的用户上手摩擦大、易放弃 | 用户持续用「缺一键入口」的体验，dsh 版 SDDU 交付体验与 opencode 版明显落差 |
| install-dsh.sh 仅做纯文件复制，不承担自动构建，与 opencode install.sh 的 8 步全自动差异大 | 从源码安装的用户需手动 `npm run build`，流程割裂 | 每次初始安装/升级都重复手动构建，痛点反复发生 |

## 2. 用户画像
> 描述受影响用户角色及其场景，回答"谁遇到了什么问题"

| 用户角色 | 典型场景 | 关键痛点（用户原话） | 当前应对方式 |
|---------|---------|-------------------|------------|
| opencode 版 SDDU 用户迁移到 dsh | 已熟悉 opencode 的 curl 一行安装，切换 dsh 时发现要四步 | "和现有的 opencode 一键安装差异很大" / "整体缺一个一键入口" | 忍受四步流程，或退回 opencode |
| 纯 dsh 新用户 | 在一个没有 SDDU 的全新 dsh 环境安装 SDDU | "都是在一个没有 sddu 的 opencode/dsh/xxx 环境，安装 sddu" | 逐条照 README 手动操作，卡在 build / 启动环节 |

## 3. 问题清单
> 按影响程度分级梳理所有识别到的问题，每项赋予唯一编号 Q-xxx

### 3.1 核心问题
> 影响面大、频率高、用户强烈感知

| ID | 问题描述 | 影响范围 |
|----|---------|---------|
| Q-001 | dsh 安装流程缺一键引导层。opencode 侧有 `bootstrap.sh`（curl 一行 → clone + `install.sh` 全自动），dsh 侧需手动 clone 仓库 + `npm run build` + `scripts/install-dsh.sh` + `npx @deepseek-ai/dsh web` 四步，无任何一键入口。用户原话："整体缺一个一键入口"。 | 所有 dsh 版 SDDU 的全新环境安装者 |
| Q-002 | install-dsh.sh 仅做纯文件复制，不承担自动构建。opencode `install.sh` 是 8 步全自动（检查源码 → clean+build → 定位分发 → 建目录 → 复制 → 版本检测 → 配置 → 初始化），dsh `install-dsh.sh` 只把已构建的 `dist/dsh/skills` 复制到目标，用户需另跑 `npm run build`。用户原话："和现有的 opencode 一键安装逻辑差异很大"。 | 所有从源码安装/升级的用户 |

### 3.2 次要问题
> 影响面中等、或为核心问题的衍生问题

| ID | 问题描述 | 影响范围 |
|----|---------|---------|
| Q-003 | 安装后如何启动 dsh 无引导。装完 skill 后需用户自行 `npx @deepseek-ai/dsh web`，安装脚本只打印落位自检清单，不衔接「下一步怎么用 / 怎么启动」。 | dsh 新用户 |
| Q-004 | 升级跟随无「一键」载体。dsh 快速迭代期，升级跟随是一份手工核对清单（`upgrade-following.md` 步骤 0~6），无对应一键升级脚本，痛点与初始安装同源且反复发生。用户确认「初始 + 升级都痛」。 | 已装用户的每次升级 |

### 3.3 潜在问题
> 目前影响小但可能恶化，或信息不足待验证

| ID | 问题描述 | 影响范围 |
|----|---------|---------|
| Q-005 | dsh 无 CLI，「启动 dsh web」无法被脚本完全自动化（2026-08-14 快照）。bootstrap 只能装到 skill 落位，拉起 `dsh web` 仍需用户手动，一键体验的收尾环节可能不完整。 | 追求全自动的体验预期 |
| Q-006 | dsh 处于 developer preview，安装链路依赖的 dsh 事实（skill 发现 / rank / 目录约定）可能已与 2026-08-14 快照漂移，bootstrap 若按旧快照假设落位会失效。 | 安装链路的可靠性 |
