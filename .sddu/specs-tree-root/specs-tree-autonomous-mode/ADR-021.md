# ADR-021: plugin.ts 职责拆分与决策代理层模块化

## 状态

PROPOSED

## 背景

`src/adapters/opencode/plugin.ts`（537 行）作为插件唯一入口，混杂了 4 类职责：

1. **初始化**：StateMachine / DependencyChecker / ParentStateManager / AutoUpdater 的实例化与全局单例管理
2. **辅助函数**：`legacyStatusToPhase` 映射、`readFeatureState` / `writeFeatureState`
3. **3 个状态工具**：`sddu_update_state` / `sddu_tag_feature` / `sddu_get_all_states`
4. **4 个生命周期 hook**：`session.created` / `file.edited` / `session.idle` / `session.end`

单文件职责混杂，难以快速理解「plugin 到底做了什么」。且本 Feature（FR-AUTONOMY-001）需在适配器层新增「决策代理层」（question.asked 拦截 + reply 代答，见 ADR-018），若继续塞入 plugin.ts 将使其更加臃肿。

## 决策

将 plugin.ts 按职责拆分为 5 个模块，plugin.ts 瘦身为「初始化 + 组装」入口：

```
src/adapters/opencode/
├── index.ts          # 公共出口（不变，re-export plugin）
├── plugin.ts         # 入口：初始化各组件 + 组装返回 { tool, hooks }（瘦身）
├── tools.ts          # 3 个状态工具 + 辅助函数（legacyStatusToPhase / read / write）
├── hooks.ts          # 4 个生命周期 hook
├── decision-proxy.ts # 【新增】question.asked 拦截 + reply 代答（方案 D 核心）
└── templates/opencode.json.hbs  # 不变
```

拆分原则：

1. **plugin.ts 只保留「编排」**：实例化各组件、注入依赖、返回工具与 hook 的组合对象，不含具体实现。
2. **tools.ts** 收敛 3 个状态工具及其共享辅助函数，对外 tool 名保持不变（`sddu_update_state` / `sddu_tag_feature` / `sddu_get_all_states`），行为零变化。
3. **hooks.ts** 收敛 4 个生命周期 hook，行为零变化。
4. **decision-proxy.ts** 独立承载决策代理层，与既有状态工具解耦，便于本 Feature 单独实现与实测（避免污染既有稳定代码）。
5. **全局单例（globalAutoUpdater / globalStateMachine）由 plugin.ts 持有并注入**给 hooks.ts / decision-proxy.ts，避免跨模块共享可变全局状态。

## 后果

**正面**：
- plugin.ts 从 537 行瘦身为「组装入口」，一眼看清 plugin 由「tools + hooks + decision-proxy」三部分构成。
- 决策代理层独立模块，本 Feature 的实现与实测不污染既有状态工具代码。
- 与 `src/state/` 的「按职责拆分文件」风格一致，降低后续维护成本。

**负面与需验证点**：
- 引入对既有稳定代码的重构，需回归验证 3 个工具与 4 个 hook 的行为不变（build 后 diff 验证 + 既有测试套件覆盖）。
- 全局单例改为「plugin.ts 持有 + 注入」的依赖传递方式，需确认 hooks / decision-proxy 的签名设计不破坏既有调用。
- 拆分是「为容纳决策代理层而做的必要重构」，若本 Feature 范围收紧，可将拆分降级为可选优化（但推荐保留，因 plugin.ts 已显臃肿）。
