# ADR-020: 决策追溯（Q-007）纳入本期范围及原 Roadmap 提案处置

## 状态

PROPOSED

## 背景

spec 的两个开放问题在此一并解决：

1. **开放问题 #2（Q-007）**：决策追溯是否纳入本期范围——是否记录 `sddu-auto` 代答决策的日志与依据，供用户事后回溯与纠偏。Q-007 被 discovery 列为「潜在问题」，其价值在于：用户最后才看效果（US-004），中间 sddu-auto 替用户做了哪些决策、依据是什么，若无记录则难以回溯与纠偏（Q-006 跑偏风险会因此放大）。
2. **开放问题 #5（R-002）**：与原 Roadmap 提案 FR-AUTONOMY-001 的关系处置——原提案（分级自主 L0/L1/L2 + 四维决策边界模型）已被 spec 明确降级，是否需正式废弃/替换。

## 决策

**1. Q-007 决策追溯：轻量纳入本期范围**

在 Feature 目录下新增一份轻量产物 `auto-decisions.md`，记录代答的关键决策点：

- 每个决策点记录：`决策点`（子 Agent 提问）、`采纳的决策`（代答返回）、`决策依据`（启动诉求引用 + 项目上下文）、`是否硬决策`（有无启动诉求锚定）。
- 定位为 **sddu-auto 流程的附加追溯产物**，不属于 7 阶段标准产物清单，因此不违反 NFR-002「产物文件命名与结构上与普通 sddu 一致」（该一致性仅约束 discovery.md~validate.md 七份标准产物）。

**理由**：Q-007 是「验收与纠偏效率」的关键支撑——用户放手跑完、最后统一验收（US-004），若中间决策无痕，跑偏时用户无从纠偏，直接违背 NG-003 背后「用户自行改走其他入口」的隐含前提（改走的前提是能看清偏在哪）。且实现成本极低，投入产出比高。

### 架构调整（2026-08-15，review R1 改进项 2 处置）

**决策追溯的生产者职责由「sddu-auto 主 Agent」调整为「decision-proxy（协议层）」**：

- **原因**：代答发生在 question 工具的协议层（decision-proxy），FR-006 要求被拦截提问不达用户，主 Agent（sddu-auto）同样收不到这些提问，因此原「由 sddu-auto 在执行阶段维护 auto-decisions.md」在架构上不可执行——决策者（proxy）与记录者（模板）之间无数据通道。
- **落地**：`decision-proxy.ts` 在代答路径中将「被拦截提问 + 决策结果」追加写入 `specs-tree-<feature>/auto-decisions.md`（依据 `auto-context.json` 的 `featureName` 定位目录；`featureName` 未采集时跳过写入，追溯失败绝不阻塞代答）。sddu-auto 模板 §6 相应改为：主 Agent **不负责写入**，仅负责①启动阶段写入 `featureName` 供定位；②完成汇报前读取统计决策点数量。
- **本调整不改变 ADR-020 的定位结论**：`auto-decisions.md` 仍为附加追溯产物，不参与状态机 requiredFiles 校验、不触发 phase 流转。

**2. 原 Roadmap 提案处置：建议废弃并由本 Feature 替换**

- **建议**：原 FR-AUTONOMY-001 提案（分级自主 L0/L1/L2 + 四维决策边界模型）标记为**废弃**，其定位由本 Feature（「新增 sddu-auto 代理决策层」）替换。
- **依据**：discovery.md 深度访谈已确认用户真实诉求与原提案「根本性差异」——原提案是「改造现有 Agent 的提问行为」，真实诉求是「新增独立调度 Agent 插入代理决策层」。方向不同，非并存关系。
- **处置边界**：实际修改 `.sddu/ROADMAP.md` 属 roadmap 阶段职责。plan 阶段给出建议并记录于此，不越界修改 ROADMAP.md。

## 后果

**正面**：
- 轻量决策追溯让「放手跑完、最后验收」具备可回溯性，显著降低用户纠偏成本，缓解 Q-006 跑偏风险。
- 原提案处置建议明确，消除 Roadmap 语义残留（R-002 解决）。

**负面与注意事项**：
- 新增 `auto-decisions.md` 是 7 阶段标准产物之外的附加文件，需在 sddu-auto prompt 中明确「该文件不参与状态机 requiredFiles 校验、不触发 phase 流转」，避免与 `machine.ts` 的产物校验逻辑冲突。
- 决策追溯记录粒度由 decision-proxy 控制（记录每一次被拦截的提问与代答，粒度天然受限于「子 Agent 实际发起的提问数」，不会无限膨胀）。主 Agent 模板不再定义「关键决策点判定阈值」（该职责随生产者迁移到协议层）。
- 决策追溯依赖 `auto-context.json` 中的 `featureName` 定位 Feature 目录：若启动阶段未写入 `featureName`，追溯将静默跳过（不阻塞代答），属可接受的降级。
- 原提案废弃属 roadmap 阶段待办，若 roadmap 阶段未同步执行，存在短暂语义并存期——由 roadmap 阶段跟进，不在本期 plan 范围。
