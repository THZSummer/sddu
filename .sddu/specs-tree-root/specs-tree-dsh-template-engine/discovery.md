## 1. 问题定义
> 概括核心问题及其业务影响，回答"为什么需要关注"

| 核心问题 | 业务影响 | 不解决的成本 |
|---------|---------|------------|
| dsh 侧 SDDU 输出模板未落位：install-dsh.sh 只装 11 个 SKILL.md，`templates/output/*.hbs` 模板文件未随 skill 落位，SKILL.md 指令引用的模板路径在 dsh 侧不存在 | dsh 侧各阶段产物无模板约束，输出格式不可控 | 用户原话：没有输出模板，输出的效果就不可把控，严重影响体验 |
| dsh 无模板渲染机制：模板约束靠 LLM 读模板文件后遵循（软约束），弱于 opencode 的代码渲染（Handlebars） | 输出格式约束力弱，可能漂移 | 输出可靠性下降，各流程产物质量不稳 |

## 3. 问题清单
> 按影响程度分级梳理所有识别到的问题，每项赋予唯一编号 Q-xxx

### 3.1 核心问题
> 影响面大、频率高、用户强烈感知

| ID | 问题描述 | 影响范围 |
|----|---------|---------|
| Q-001 | dsh 侧模板文件未落位。SDDU 核心架构自带 30 个输出模板（`src/templates/outputs/*.hbs`：10 个阶段输出 + 20 个 docs），opencode 侧由插件分发（`.opencode/plugins/sddu/templates/output/`）并代码渲染；dsh 侧 `install-dsh.sh` 只装 11 个 SKILL.md，模板 `.hbs` 文件未随 skill 落位，SKILL.md §6 指令引用的模板路径在 dsh 侧不存在，LLM 无模板可读。 | 所有 dsh 平台 SDDU 流程产物 |
| Q-002 | dsh 无模板渲染机制（软约束）。opencode 靠 Handlebars 代码渲染强约束输出；dsh 无渲染 seam（2026-08-14 快照未覆盖），只能靠 LLM 读模板文件 + 遵循指令，约束力弱于 opencode。 | 输出格式可靠性 |

### 3.2 次要问题
> 影响面中等、或为核心问题的衍生问题

| ID | 问题描述 | 影响范围 |
|----|---------|---------|
| Q-003 | SKILL.md 模板查找路径失效。当前指令写「用户自定义 `.sddu/templates/agents/output/*.hbs` > 插件内置 `.opencode/plugins/sddu/templates/output/*.hbs`」，后者的 `.opencode` 路径在 dsh 侧不存在，需改为 dsh 侧实际落位路径。 | 模板查找指令正确性 |
| Q-004 | docs 全景模板（20 个 `sddu-docs-*.hbs`）同样未落位，@sddu-docs 在 dsh 侧无模板约束。 | @sddu-docs 产物 |

### 3.3 潜在问题
> 目前影响小但可能恶化，或信息不足待验证

| ID | 问题描述 | 影响范围 |
|----|---------|---------|
| Q-005 | 模板与 SKILL.md 的单一来源链路需打通：模板源头在 `src/templates/outputs/`，需由 `build-dsh-skills.cjs` 构建时分发到 dsh 侧，避免手工维护两份。 | 构建链路一致性 |
| Q-006 | 软约束下 LLM 可能不严格遵循模板，输出仍可能漂移（约束力上限低于 opencode 代码渲染）。 | 输出可靠性上限 |
