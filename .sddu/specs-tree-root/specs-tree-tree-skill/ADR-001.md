# ADR-001: sddu-tree Agent→Skill 降级 — 一步到位全量迁移方案

## 状态
PROPOSED

## 背景

SDDU 当前拥有 11 个核心 Agent，其中 @sddu-tree 是唯一的纯辅助 Agent（不参与 7 阶段主流水线，仅扫描 `.sddu/` 目录生成 TREE.md 导航）。FR-SKILL-001（SDDU Skill 系统）已确立「Agent 固定 + Skill 扩展」架构原则，@sddu-tree 的职责（6 步流程化工作流：扫描→检测缺失→读取文件→生成 TREE→验证已有→输出报告）完全符合 Skill 化条件——无状态、无独立生命周期需求、高度流程化。

保留 @sddu-tree 为独立 Agent 带来的问题：
1. **违反自定架构原则**——SDDU 自己的 Agent 新增门禁在自己身上失效
2. **Token 成本无效消耗**——每次触发启动独立 subagent（含完整 265 行 prompt + opencode.json 上下文），而非 Skill 模式的按需加载
3. **维护成本分散**——8 个主流程 Agent 模板硬编码 `@sddu-tree` 调用指令，任何 TREE 逻辑变更需跨 8+ 文件全局替换
4. **缺少降级实战范本**——FR-SKILL-001 的降级模型停留在理论层面，后续 FR-BUG-001、FR-WORKTREE-001、@sddu-docs 的降级决策缺乏真实数据支撑

## 决策

**我们决定采用「一步到位全量迁移」方案降级 @sddu-tree：**

1. **创建 SKILL.md**（FR-001）——将原 Agent 265 行模板的完整逻辑迁移为框架级 Skill 文件 `.sddu/skills/sddu-tree/SKILL.md`，使用 Progressive Disclosure 三层结构（frontmatter → Stage 2 概述 → Stage 3 详细 body）。弃用 Agent 专属骨架章节（执行顺序、依赖关系、输出模板声明）。

2. **原子迁移**（FR-002 + FR-003 + FR-004 + FR-008）——单次提交完成：
   - 从 `opencode.json` 移除 sddu-tree subagent 注册条目（L62-66）
   - 删除 `src/templates/agents/sddu-tree.md.hbs` 源模板
   - 将 8 个主流程 Agent 模板中的硬编码 `@sddu-tree` 调用指令替换为 Skill 发现引用声明
   - 更新 `sddu.md.hbs` coordinator 的 Agent 清单表和数量统计

3. **同步与验证**（FR-005/FR-006/FR-007）：
   - 通过 `sddu-skill-sync` 将 SKILL.md 同步到实际域
   - 自举验证：sddu-tree Skill 扫描 `.sddu/skills/` 目录并生成 TREE
   - 等价性验证：diff 对比降级前后 TREE 输出

### 备选方案及拒绝理由

| 方案 | 拒绝理由 |
|------|---------|
| **方案 B：渐进式双轨过渡**（Stage 1 Skill + Agent 并行 → Stage 2 移除 Agent） | ① 过渡期存在双写 TREE 风险（Agent 和 Skill 同时触发）；② 增加流程复杂度（两阶段协调）；③ 与 spec FR-008 原子迁移要求冲突 |
| **方案 C：SKILL.md 包装 Agent**（保留 Agent 注册，将 prompt 指向 Skill 内容） | ① 未解决核心问题——仍保留 subagent 启动开销；② 未达成「Agent 清单收缩为 10 个」目标；③ 未消除架构不一致 |

## 后果

### 正面影响
1. **架构一致性**——Agent 清单从 11 个收缩为 10 个，消除辅助 Agent 类别，完全对齐「Agent 固定 + Skill 扩展」原则
2. **Token 效率提升**——Skill 模式按需加载，不产生额外 subagent 启动开销。预估每次工作流会话节省 2-3 次 subagent 启动的 token 消耗
3. **维护成本降低**——TREE 生成逻辑集中于单一 SKILL.md 文件，不再横跨 8+ 模板。修改一处即可生效
4. **建立降级范本**——产出完整的 Agent→Skill 降级实战记录（审计→迁移→替换→同步→验证→自举），为后续 FR-BUG-001、@sddu-docs 降级提供可复用 checklist

### 负面影响
1. **用户显式调用习惯中断**——`@sddu-tree` 命令不再可用。用户需通过 `@sddu "扫描 .sddu/ 目录"` 或等待自动触发。缓解：ROADMAP/CHANGELOG 中记录行为变更
2. **回滚依赖 git**——出问题时需 `git revert` 整个提交。缓解：git 历史完整保留原模板和注册条目，回滚无数据丢失风险
3. **TREE 生成一致性**——不同 Agent（不同 LLM）加载 Skill 后的输出可能有轻微偏差。缓解：Skill body 内嵌严格格式模板 + FR-007 等价性验证

### 技术债务
- sddu-docs.md.hbs 中的三 Agent 边界表（当前包含 @sddu-tree 维度）需重构为二 Agent 表或包含 Skill 维度的新格式——这将在 FR-004 替换过程中一并处理
- `install.sh` 和 `install.ps1` 中的 help 信息提及 @sddu-tree 需同步更新
