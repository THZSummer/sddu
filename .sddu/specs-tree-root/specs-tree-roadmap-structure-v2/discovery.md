## 1. 问题定义
> 概括核心问题及其业务影响，回答"为什么需要关注"

**动机（用户已拍板，D1）**：上游 Feature（FR-ROADMAP-TPL-001 / v4.1.0）已把 `.sddu/ROADMAP.md` 从"随心所欲"收敛为**固定的 8 个 H2 章节**，消除了"章节集合与顺序漂移"。但章节**内部的组织逻辑**仍是扁平的、混装的 —— 用户在多轮对话中诊断出的原话是：**「『下一步行动』就是个横切杂物箱，什么都往里装」**。本 Feature 的动机是把模板从"扁平 8 章"重构为**概览层 + 详情层**的分层结构：三个主体（**版本 / 特性 / 问题**）各有清单与详情各一章，依赖与风险不再独立成章而是融入三主体，优先级回退为 P0/P1/P2。

| 核心问题 | 业务影响 | 不解决的成本 |
|---------|---------|------------|
| **「下一步行动」是横切杂物箱（P1）**：技术债 / 决策 / 执行批次 / 版本级行动混装于一章，与版本、特性、优先级三方发生归属侵占 | 同一信息在多章重复且口径不一；读者无法仅凭章节名判断内容归属，规划可读性持续下降 | 结构虽已固定，内容仍持续漂移；增量合并的保留区越滚越杂，v4.1.0 消除的是"章节漂移"而非"内容漂移" |
| **双时间轴打架（P2）**：版本轴（§2 版本总览 / §5 版本规划详述）与「立即 / 短期 / 中期 / 远期 + Phase / Wave」（§7 下一步行动）并存，同一信息两种表达 | 两套时间轴必然漂移、互相矛盾，读者无法确定以哪条为准；下游无法稳定解析"何时做什么" | 每次更新需人工对齐两轴，遗漏即产出自相矛盾文档；时间信息熵随版本增长 |
| **问题无独立身份（P3）**：问题内容散落在「依赖与风险」表与「下一步行动」待办里，无登记制台账、无稳定编码、无生命周期 | 项目级问题无法被稳定引用与追踪（开放 → 已转化 → 已关闭）；同一问题反复出现、反复遗忘 | 问题治理无闭环，技术债 / 风险 / 决策长期悬空，无任何承载位（P5 同源） |

> **结构性根因**：现行 8 章的划分维度是"**文档块**"（总览 / 详述 / 风险 / 行动 / 修订），而非"**管理三主体**"（版本 / 特性 / 问题）。维度不对齐，必然出现横切杂物箱与双时间轴。本 Feature 的重构方向是**按三主体重新切分**，并叠加"清单 ↔ 详情"两层粒度。
