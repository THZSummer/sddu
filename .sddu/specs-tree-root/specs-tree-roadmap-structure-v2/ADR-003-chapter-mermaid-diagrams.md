# ADR-003: 章首 Mermaid 图 — GitHub 原生渲染、零构建依赖、preserve 区静态演进

## 状态
ACCEPTED

## 背景

discovery 的 Q-006：旧产物全为文字与表格，版本 / 特性 / 问题的归属与分布无法一眼把握。用户已拍板（D2）：**每章章首加 1 个 Mermaid 图**描述本章。spec FR-003 / NFR-005 已固化为：每章恰 1 个 ` ```mermaid ` 块、每图 ≤10 行、语法合法（GitHub 可渲染）、节点名无空格陷阱。spec 把「图类型 / 语法合法性的具体实现」显式移交 plan / validate。

约束与事实：

- **产物即 Markdown**（`.sddu/ROADMAP.md`），GitHub 原生渲染 ` ```mermaid ` 围栏 → 零依赖可用。
- **零运行时代码**（NFR-006）：不得引入图形库 / 渲染脚本 / 构建期图生成。
- **EC-007**：图损坏时文档仍可读（退化为代码块，不阻塞正文与其他章节）。
- **preserve 区的图随区逐字保留**（FR-003）：图位于 zone 内、entry 外时，会随该区被原样保留。需在「图随区保留（不丢，但可能过时）」与「图随区重建（总最新，但可能覆盖人工调整）」之间取舍。

## 决策

采用 **Mermaid 章首图**，每章恰 1 图：

1. **图类型**：结构关系用 `flowchart LR`（§1 定位 / §2 版本时间线 / §5 版本-特性-问题关系 / §6 特性归属 / §7 问题归属 / §8 修订时间线）；分布用 `pie`（§3 特性状态分布 / §4 问题类型分布）。
2. **落位**：图放**各章对应 zone 内顶部**——`rewrite` 区图随区整体重建（§1/§2/§3）；`preserve` 区图在 zone-open 之后、**首个 entry 之前**，随区逐字保留（§4~§8）。
3. **语法护栏**：
   - 节点标识符使用无空格英文 / 短横线（如 `V100` / `F_RDSTRUCT`）；
   - 节点标签含中文或空格时一律引号包裹（如 `V100["v1.0.0 发布"]`）；
   - 每图 ≤10 行；` ```mermaid ` 与闭合围栏必须配对；
   - 图仅表达**结构关系 / 分布**，不承载数据快照（避免与正文数据不一致）。
4. **preserve 区静态演进**：preserve 区的图随区逐字保留 → 结构原型一旦生成即稳定；若需调整，由用户在对应 preserve 区显式编辑（并随修订记录登记）。

## 后果

**正向**：
- Q-006 消解：读者可一眼把握版本 / 特性 / 问题的归属与分布，降低长文档阅读成本。
- GitHub 原生渲染、零构建依赖、零运行时代码（NFR-006 合规）。
- 语法可静态校验（围栏计数、行数、空格陷阱 grep）+ 沙箱解析（V-03 / V-05），失败模式可检测。
- 图损坏时退化为代码块，不阻塞正文（EC-007），文档可读性有兜底。

**代价 / 残余风险**：
- preserve 区的图随区保留 → 结构演进（如新增章节）后旧图可能过时；缓解：图仅表达静态结构关系、不表数据；结构变更属模板变更，随修订记录登记。
- 节点名空格陷阱是 Mermaid 常见错误 → 由统一命名规范（英文标识符 + 引号包裹标签）与静态 grep 拦截。
- 每图 ≤10 行限制了表达复杂度 → 与「章首一图、概览性质」定位一致，详情下沉到表格 / entry。

## 备选方案与否决理由

| 备选 | 否决理由 |
|------|---------|
| ASCII 图（+--+ / \| 字符画） | 无统一渲染器、终端字体宽度不一易错位；GitHub 无原生美化；维护成本高于 Mermaid，且无法静态验证语法 |
| 引入图形库 / 构建期生成 PNG / SVG | 违反零运行时代码（NFR-006）与工程边界；需新增构建链路与二进制资产 |
| 外链图片（托管服务 URL） | 依赖外部服务、易失效；违反 NG-007（单文件产物）与外链稳定性原则 |
| 全章不加图，仅靠表格 | Q-006 未解，与 D2 拍板结论冲突 |
| 图放 zone 外（章首紧邻） | 位于 zone 外会被增量合并视为「非保留内容」而可能被覆盖；且违反 FR-003「图位于 zone 内」的落位要求 |
