# ADR-001：「源目录 + 实际目录」双层架构

## 状态
ACCEPTED

## 背景

SDDU Skill 系统需要同时满足两个需求：
1. SDDU Agent 需要独立于 LLM Agent 工具（OpenCode）的 Skill 发现路径——确保平台无关
2. LLM Agent 需要能通过原生机制（OpenCode 扫描 `.opencode/skills/`）加载 Skill body

单一目录方案无法同时满足两者：
- 纯 `.sddu/skills/`：OpenCode 原生不扫描该路径 → `skill()` 工具无法加载 → 破坏 LLM Agent 原生发现流程
- 纯 `.opencode/skills/`：SDDU Agent 扫描逻辑与 OpenCode 耦合 → 换 LLM Agent 工具后需重修

## 决策

我们决定采用 **「源目录 + 实际目录」双层架构**：

| 层级 | 路径 | 维护者 | 用途 |
|------|------|--------|------|
| 用户级 Skill 源目录 | `.sddu/skills/` | 用户手写，git 管理 | SDDU Agent 扫描发现 + 用户编辑维护 |
| 框架级 Skill 源目录 | `.opencode/plugins/sddu/skills/` | SDDU 插件分发 | SDDU Agent 扫描发现 |
| 实际目录 | `.opencode/skills/` | 拷贝同步（脚本自动） | OpenCode 原生 skill 机制加载 Skill body |

**两套发现流程**：
- 流程①：SDDU Agent 扫描源目录 → 获知可用 Skill 名称 → 与平台无关
- 流程②：LLM Agent 扫描实际目录 → 加载 Skill body → 利用 OpenCode 原生机制

**拷贝机制**：安装/更新时，全量拷贝源目录 Skill 到实际目录。

## 后果

### 正面
- SDDU Agent 的 Skill 发现与 LLM Agent 工具完全解耦——切换到 Codex/Claude Code 时只需改变实际目录的拷贝路径，不影响 SDDU 自有逻辑
- 用户可直接在 `.sddu/skills/` 下手写 Skill，同时受 git 版本控制（随项目仓库分发）
- 框架级 Skill 随 SDDU 插件分发，一次更新覆盖所有用户
- 用户可通过 `@skill-name` 手动调用 Skill——因为实际目录中 Skill 对 OpenCode 完全可见

### 负面
- 需维护「源目录 → 实际目录」的拷贝同步机制——引入额外基础设施
- 存在拷贝不一致的窗口期（源目录变更后、同步前）
- 用户手动修改实际目录的 Skill 会被下次同步覆盖

### 缓解
- `sddu skill doctor` 诊断命令可检测源目录与实际目录的一致性
- 文档明确说明实际目录由 SDDU 管理，用户应编辑源目录
- 同步通过 `install.sh` 的标准化函数执行，减少人为错误
