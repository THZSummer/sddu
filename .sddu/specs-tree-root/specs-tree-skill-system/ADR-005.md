# ADR-005：框架级 Skill 源码在仓库中的存放路径——`src/skills/`

## 状态
PROPOSED

## 背景

框架级 Skill（如 `sddu-skill-creator`、`sddu-skill-discovery`）的 SKILL.md 源码需要存储在 SDDU 源码仓库中。构建后需打包到 `dist/sddu/skills/`，由 `install.sh` 最终部署到目标项目的 `.opencode/plugins/sddu/skills/`。

三个候选源码路径：
- **方案 A**：`src/skills/`（与 `src/templates/agents/` 平级）
- **方案 B**：`src/templates/skills/`（与 Agent 模板一起）
- **方案 C**：`.opencode/plugins/sddu/skills/`（仓库内直放，零构建拷贝）

## 决策

我们决定采用 **方案 A（`src/skills/`）**。

**源码目录结构**：
```
src/
├── skills/                              ← NEW — 框架级 Skill 源码
│   ├── sddu-skill-creator/
│   │   └── SKILL.md
│   └── sddu-skill-discovery/
│       └── SKILL.md
├── templates/
│   ├── agents/                          ← 已有 — Agent 模板 (.hbs)
│   │   └── sddu-*.md.hbs
│   └── outputs/                         ← 已有 — 输出模板 (.hbs)
│       └── sddu-*.md.hbs
├── adapters/
├── state/
└── shared/
```

**构建链**：
```
src/skills/                  （源码）
    │  package.cjs 新增拷贝
    ▼
dist/sddu/skills/            （打包产物）
    │  install.sh 第 5 步已拷贝 .opencode/plugins/sddu/
    ▼
目标项目 .opencode/plugins/sddu/skills/  （框架级 Skill 源目录）
    │  install.sh 第 8 步新增拷贝
    ▼
目标项目 .opencode/skills/  （实际目录）
```

## 后果

### 正面
- **语义清晰**：`src/skills/` 直接表达「SDDU 框架级 Skill 的源码」，目录命名 self-documenting
- **与 Agent 模板平级但分离**：`src/templates/agents/` 管「Agent 如何执行」，`src/skills/` 管「Skill 执行什么」——职责边界清晰
- **构建流程改动最小**：`package.cjs` 只需新增约 10 行 `fs.copy(srcSkillsDir, dstSkillsDir)`——不改动 `build-agents.cjs`（Skill 是纯 Markdown，不需 Handlebars 编译）
- **未来可扩展**：`src/skills/` 下可继续添加更多框架级 Skill（如 `sddu-bug-fix-workflow`、`sddu-rational-prompts` 等 FR-015/FR-016 中规划的 Skill）

### 负面
- 在 `src/` 下引入一个新顶层子目录（从当前 5 个子目录增至 6 个）
- `package.cjs` 仍需改动——但改动量为新增一个 `fs.copy` 调用，风险低

### 未选择 B 的原因
- Skill 不是 Handlebars 模板——`src/templates/` 下的文件经过 `.hbs` → `.md` 的编译过程（Handlebars 变量替换）
- SKILL.md 是纯 Markdown——不需要也不应该经过 `build-agents.cjs` 的模板编译流程
- 语义混淆——Agent 模板和 Skill 内容是一类文件吗？前者是「行为定义」，后者是「可执行知识」。分目录维护更清晰

### 未选择 C 的原因
- `.opencode/` 目录在 SDDU 仓库中当前为空——如果直接在该路径放置框架 Skill，需要将整个 `.opencode/` 目录纳入分发流程
- 与现有「从 `dist/sddu/` 分发到目标项目」的构建模式不一致——install.sh 期望从分发目录读取插件文件
- `.opencode/` 包含运行时文件（如本地安装时的 agents/）——混入 Skill 源码可能造成源码仓库与运行时环境混淆
