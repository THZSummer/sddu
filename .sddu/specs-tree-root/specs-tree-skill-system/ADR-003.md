# ADR-003：Skill 发现流程——`sddu-skill-discovery` Skill vs Agent 模板硬编码

## 状态
PROPOSED

## 背景

SDDU Agent 在需要发现可用 Skill 时（FR-021），需要知道「如何扫描源目录、如何识别 Skill、如何区分框架级 vs 用户级 Skill、如何获取 Skill 名称清单」。该发现逻辑可以通过两种方式实现：

- **方案 A**：在每个 Agent 的 `.hbs` 模板中硬编码扫描路径和识别规则（如「扫描 `.sddu/skills/` 和 `.opencode/plugins/sddu/skills/` 中的有效 SKILL.md」）
- **方案 B**：创建一个独立的框架级 Skill `sddu-skill-discovery`，在其 SKILL.md body 中描述完整的源目录扫描流程。所有 Agent 模板中硬编码引用该 Skill（自然语言指令）。Agent 需要发现 Skill 时加载该 Skill 获取指引。
- **方案 C**：coordinator（@sddu）集中扫描源目录，通过路由上下文传递 Skill 清单给子 Agent

## 决策

我们决定采用 **方案 B（`sddu-skill-discovery` Skill + Agent 模板引用）**。

**实施方式**：

1. 创建 `src/skills/sddu-skill-discovery/SKILL.md`（框架级 Skill）：
   - Frontmatter: `name: sddu-skill-discovery`, `description: "当 SDDU Agent 需要发现可用的 SDDU Skill 时加载此 Skill，描述如何扫描源目录（.sddu/skills/ 和 .opencode/plugins/sddu/skills/）、识别有效的 SKILL.md、区分框架级（sddu- 前缀）和用户级（无前缀）Skill"`
   - Body: 包含完整的源目录扫描流程——路径、识别规则、命名空间分类、SKILL.md 加载方式。明确标注「仅覆盖 SDDU 源目录扫描（流程①），不涉及 LLM Agent 原生发现机制」

2. 在 12 个 SDDU Agent 的 `.hbs` 模板中新增「Skill 发现与同步」章节：
   ```
   ## Skill 发现与同步
   当需要发现或使用 SDDU Skill 时，参考 `sddu-skill-discovery` 这个 Skill 了解如何扫描和发现可用的 SDDU Skill。
   
   SDDU Skills 分两级：
   - 用户级 Skill 源目录：`.sddu/skills/`
   - 框架级 Skill 源目录：`.opencode/plugins/sddu/skills/`
   
   所有 Skill 的实际运行副本位于 `.opencode/skills/`。
   若实际目录中不存在 SDDU Skill，请参考 `sddu-skill-sync` Skill 了解如何将源目录中的 Skill 同步到实际目录。
   ```

## 后果

### 正面
- **三元自举闭环**：`sddu-skill-discovery` + `sddu-skill-creator` + `sddu-skill-sync` = 「用 Skill 发现 Skill + 用 Skill 创建 Skill + 用 Skill 同步 Skill」，三者并列构成 Skill 生态的核心三元闭环（spec v2.3.1 §5.7）
- **单一真相来源**：发现逻辑在一个 Skill 中定义——修改扫描策略只需更新一个文件
- **新增 Agent 自动获得**：未来新增的 Agent 只需在模板中包含引用
- **完全对齐 spec G-007/G-008**：既创建了独立 Skill 目录，又在模板中硬编码引用

### 负面
- **依赖 OpenCode Agent 对「参考某 Skill」的自然语言指令的响应行为**——Agent 可能需要显式调用 `skill()` 工具加载。若 Agent 不主动加载，Skill 清单始终为空
- 增加了一个额外的 Skill 文件需要维护

### 未选择 A 的原因
- 违反 DRY——12 个 Agent 模板中重复维护相同扫描逻辑
- 扫描策略变更需修改 12 个文件
- spec G-007 明确要求 `sddu-skill-discovery` 作为独立 Skill 存在——方案 A 未满足该要求

### 未选择 C 的原因
- `task()` 调度绕过 coordinator——用户直接调用 `@sddu-build feature-x` 时不经过 coordinator，子 Agent 无法获得 Skill 清单
- coordinator 内复杂度增加——与「coordinator 只路由不设计」的设计原则冲突
