# ADR-004：Agent 模板中 Skill 发现的三阶段渐进披露模型

## 状态
PROPOSED

## 背景

ADR-003 确定通过 `sddu-skill-discovery` Skill 统一描述发现逻辑。现在需要确定 Agent `.hbs` 模板中引用该 Skill 的具体措辞和加载策略。

核心权衡：**确定性**（强制加载）vs **context 效率**（按需加载）。关键约束：**只有 `sddu-skill-discovery` 被硬编码到模板中**，`sddu-skill-sync` 和 `sddu-skill-creator` 通过 discovery 间接发现。

## 决策

我们决定采用 **三阶段渐进披露模型**，仅硬编码 `sddu-skill-discovery` 引用：

| 阶段 | 触发条件 | 动作 | 返回 | 成本 |
|:--:|------|------|------|:--:|
| **1** | 始终默认执行 | 扫描源目录获取 Skill 目录清单（不读文件） | 目录名列表 | ~0 tokens |
| **2** | LLM 对某 skill 感兴趣 | 读取 `SKILL.md` 头部 frontmatter | name + description | ~100 tokens/skill |
| **3** | LLM 决定使用某 skill | 返回该 skill 的目录路径 | 目录路径 | 0（路径引用） |

**推荐的标准措辞**：

```markdown
## Skill 发现与同步

**默认行为（Stage 1）**：每次会话启动时，扫描以下源目录获取可用 Skill 目录清单（仅目录名，不读文件内容）：
- 用户级：`.sddu/skills/`
- 框架级：`.opencode/plugins/sddu/skills/`

**渐进式了解（Stage 2）**：获取目录清单后，根据当前任务对感兴趣的 skill 读取其 `SKILL.md` 头部 frontmatter（name + description），判断是否与任务相关。

**使用 Skill（Stage 3）**：确定使用某 skill 后，获取该 skill 的目录路径，进入目录按需读取 `SKILL.md` body 及 `references/`、`scripts/` 等资源，按指引执行。

**同步**：所有 Skill 的实际运行副本位于 `.opencode/skills/`。若 Stage 1 发现实际目录中无 SDDU Skill，则按 Stage 2→3 流程发现并加载 `sddu-skill-sync` 执行同步。
```

## 后果

### 正面
- **仅硬编码 discovery**：模板中只引用 `sddu-skill-discovery`，sync 和 creator 通过 discovery 间接发现——符合 spec G-008 的范围
- **Stage 1 零成本**：默认扫描目录名，不读文件内容，不依赖 Agent 判断「何时需要」
- **Stage 3 路径引用**：不注入 body 到 context，由 LLM 自行进入目录按需读取——context 完全由 LLM 控制
- **sync 通过 discovery 间接发现**：不需要在模板中硬编码 sync 的存在

### 负面
- **存在「Agent 不主动执行 Stage 2」的风险**：Agent 可能只看目录名而不深入读取 frontmatter
- **依赖 LLM 语义理解能力**：不同模型对三阶段指令的解读可能不同

### 验证计划
在 tasks 阶段实测 Agent 对三阶段渐进披露指令的响应行为——Agent 是否会按 Stage 1→2→3 逐步深入。若验证失败，降级为在模板中直接列出已知 Skill 名称清单。
