# ADR-011: 空钩子文件非脚手架——预置扩展点即最简拓展方式（评估 B1 非问题）

## 状态
PROPOSED（2026-11-24 用户拍板）

## 背景
多视角评估（独立开发者视角）对 workspace 骨架提出 B1：安装产物含 `.sddu-config/` 下 10×2 = 20 个**空** `sddu-<stage>-{before,after}.md` 钩子文件，独立开发者视角认为「空文件 ≠ 极简，像过度脚手架」。

## 决策
**非问题，设计如此**。理由：

1. **「极简」的定义域是 sddu 流程本身，不是安装文件数量**——v6 的极简指流程载体的极简（零 TS、零 build、零 npm、零校验脚本、文档即状态），不追求 workspace 文件数最少。文件多但每个都是纯 Markdown、按需读取，运行时成本为零。
2. **空文件是预置扩展点**——`sddu-<stage>-{before,after}.md` 以「已存在的空文件」形态告诉用户：钩子挂在这里，直接写入内容即生效。这是**最简单的拓展方式**：不需要创建目录、不需要查文档找路径、不需要记忆命名约定——文件已在正确的位置，填内容即用。
3. **可发现性优于约定优于配置**——若不预创建空文件（纯靠模块文档描述钩子路径），用户必须先读文档才能动手；预置空文件让扩展点在 `ls` 下一目了然。空文件的「信息量」不在文件内容里，而在**文件路径本身**。

## 后果
- 正面：用户拓展零门槛（填内容即生效）；扩展点可发现（目录结构自解释）；与「命名自解释 + 路径规范纯化」设计原则一致。
- 负面：安装产物多 20 个空文件（对独立开发者视角观感略重）——已判定为可接受的观感成本。
- 不可逆性：无——本 ADR 仅固化「维持现状」的决策，不引入任何变更。
