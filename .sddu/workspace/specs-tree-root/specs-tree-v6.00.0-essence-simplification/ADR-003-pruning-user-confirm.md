# ADR-003: 裁撤执行用户确认制 + v6 期间冻结 adapter 契约重构（与 v12.0.0 边界）

## 状态
PROPOSED

## 背景
spec FR-005 要求裁撤无静默执行（NG-004：已交付能力不得未经确认删除）；roadmap 已定「本质先行」次序——v12.0.0（多平台二期：adapter 契约收敛，承接 P-041）在 v6.0.0 重估中可能被建议拉前，若在 v6 期间并行做 adapter 重构将与瘦身改动面（adapters/、模板落位、安装链）冲突（风险 R-003 重复劳动）。

## 决策
> **修订（2026-11-23，ADR-005）**：决策 2 的冻结条款（v6 期间不动运行时 seam）所冻结的对象——TS 运行时——经用户拍板**整体退役**，冻结条款失效；本 ADR 的用户确认制（决策 1）与重估规则（决策 3）不变。
1. **用户确认制**：carrier-inventory.md 中所有「可删 / 可合并」项，分批提交用户显式确认后方可执行；确认记录（批次 / 项 / 用户答复）留痕于清单；未确认项一律保留。语义对齐 roadmap 中 v6.0.0 的「类 HARD-GATE」声明。
2. **冻结边界（v1.1 修订，2026-11-22 用户拍板收窄）**：v6.0.0 期间冻结的是**运行时 seam 维度**的 adapter 重构——门禁强制力、命令注册、模板渲染 seam（P-041 剩余主体，仍归 v12.0.0）；**安装与模板落位维度**按 ADR-004「统一安装范式」纳入本 Feature（通用投影器 + 声明式平台描述符）。v6 允许触及 adapters/ 的改动扩展为三类：① FR-002 口径引用对齐（纯文档性）；② 用户确认的裁撤项删除；③ ADR-004 的描述符新增与投影器接入。
3. **重估与拉前**：FR-006 重估若结论要求将 v12.0.0 拉前或合并入 v6，属路线图变更，须用户显式确认后由 roadmap 流程回填，本 Feature 不自行改版本树。

## 后果
- 正面：裁撤风险受控、决策可追溯；v6/v12 改动面互斥，避免重复劳动；范围蔓延被结构性阻止。
- 负面：v6 期间 P-041（高危技术债）继续挂账；若用户确认拉前 v12，需重排本 Feature 与路线图的任务边界（额外一轮规划成本）。
