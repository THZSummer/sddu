# ADR-002: 「本质 / 附属品」四维判定标准（D1~D4）与裁决规则

## 状态
PROPOSED

## 背景
spec FR-003 要求「本质 / 附属品」判定标准可操作（discovery A-003 假设其存在），FR-004 要求按标准对全量载体分类且无「无法归类」项。无标准则裁撤退化为逐例争吵（风险 R-002：误裁平台可用性必需品）。

## 决策
四维判定，按序评估，任一维命中即判附属品并停（短路）：

| 维 | 判定问题 | 命中→归类 |
|---|---------|----------|
| D1 流程必要性 | 删除该项后，7 阶段流程（发现→…→验证）+ 状态推进是否仍能完整走通？ | 能走通 → 附属品 |
| D2 平台特定性 | 该项是否绑定特定平台（opencode / dsh 的路径、命令、机制）？ | 是 → 附属品 |
| D3 历史包袱 | 该项是否仅服务于已完成的迁移 / 历史版本（无现存消费者）？ | 是 → 附属品-可删 |
| D4 唯一职责 | 该项职责是否与其他载体显著重叠？ | 是 → 附属品-可合并 |

- 四维全不命中 → **本质**（预期集合：7 阶段定义、三原则、两字段状态模型、文档契约、sddu.md 本身、`src/state/` 状态机实现）。
- 附属品细分：**可删**（D3 / 无消费者）/ **可换**（D2 / 平台绑定但能力需保留）/ **可合并**（D4）。
- 裁决规则：任一维判定存疑（证据不足或直觉冲突）→ 一律标「**待用户裁决**」，集中列出逐项拍板；**禁止**静默归类（spec EC-002）。
- 每项归类必须记录依据条款（如「D3：migration-status*.md 仅服务已完成的 SDD→SDDU 迁移」），保证可追溯（NFR-004）。

## 后果
- 正面：分类可执行、可复核、可追溯；边界不模糊化而是显式上交用户。
- 负面：「待用户裁决」项可能集中出现，需用户投入拍板时间（这是 spec 类 HARD-GATE 语义的固有成本）。
